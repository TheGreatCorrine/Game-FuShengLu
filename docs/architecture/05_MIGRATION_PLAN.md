# 分阶段迁移及停止条件

## Stage 1 · 只统一户账

人物键及随机键保持旧值。对完整输入做只读预检，按旧户 ID 首次出现顺序建立独立 H 映射；先登记出生户、当前户、estates、关闭户，再核对成员及掌家引用。Stage 1 的旧 API 由只读选择器提供当前现金、资产、债额，写入一律走规范账户。禁止同时维护一份可写的顶层镜像。

|旧情境|迁移或操作的精确结果|
|---|---|
|仍居 birth|根账三项只入出生户，其余 estates 各入原户；主角私钱不参加|
|已迁到 kin1|根账属于 kin1，estates.birth 属于原家；出生身份仍指 birth。迁居本身不动钱|
|独立户、后婚、手足另户|independent 与 sibling 各有独立户键。初婚现有置办家资、无其他亲属时随迁财物、手足立户扣私钱六钱都须逐笔保留；同一笔只能迁入一次。再婚保留原有子女居所|
|空户现金与欠账并存|迁移只复制；下一次原定年结才按 min(cash,debt) 抵扣。尚有资产或债则休眠；全零方可关闭。关闭年份保留|
|现户在 estates 又有账，或活人指无账户|拒绝导入并列出冲突键和两边余额。外部候选人不是在户居民；不靠建零账消除错误|

每个旧户逐项比对现金、生产资产、户债，再按人物比对私钱、按合同比对欠款。只核总和会放过两户串账。迁移不计利息、发工钱、执行履约或清算遗产。失败丢弃临时结果；原始输入可重试。已是目标 schema 则验证并原样返回。合并前保留旧命令与新命令的并行回放测试，回退以旧代码和原始输入重新执行。

## Stage 2 · 人物 ID 双遍转换

1. 建立人物命名空间。按 player、现有 npcs 数组顺序、外部 candidate 分配不可变 p 序号。新生/相识按确定性创建序号；转换后游标须大于所有已占编号。两个人同名同角色仍是两人。候选与在册出现同旧键时，必须有已验证的同人状态才合并，有冲突即报错。
2. 独立建立历史引用清单，遍历亲子、伴侣、主角配偶、户主、契约、受偿/分配记录、承诺、年谱及记忆中的参与者。对已从 candidate 清除但留有行为凭据者，可建立“仅历史引用”的最小身份，记来源、不加入户籍、不猜生卒；活跃操作发现悬空人物则拒绝。身份类型不同的引用不可混用。
3. 先造人物再连边。主角与明确的父、母关系须由旧出生规则补入；同一婚姻去重，保留既往伴侣与失偶事实。双方死亡时按旧的标记顺序与清算顺序处理；历史婚期无证据记未知。人物角色以主角为参照派生；不得因成员移户、头衔消失或死亡换 ID。
4. 将旧 id/house 字符串一并作为仅供旧版本回放使用的随机键。保留遍历顺序及分配遗产时的旧字典排序；改成 p2/p10 会改余钱归谁。保留已故人物冻结的年龄，候选人的年龄增量与普通住户分开。二次转换不得重新抽样、翻译旧键或重复生成边。
5. 先以反向适配器投影回旧字段，每条命令后逐项比较；再在新结构上验证身份和所有权。裸 JSON 的键顺序或新 ID 可以不同，玩家选择、角色对应、账、事件、随机结果不能因此漂移。

## Stage 3–5 与验证矩阵

Stage 3 才抽取领域操作及调度，保留死亡当年结算、出生时点和职业次年对产出的影响。Stage 4 再分西汉内容和观察层，普通 UI 读取可见消息，开发视图单独验证。Stage 5 用 1,000–10,000 条完整人生、多策略及成对逐年投影验收。门槛是无未解释的逐步差异；任何拟修复行为需单独提交、记录分布变化并审阅。

|回归组|夹具和可判定断言|
|---|---|
|身份、亲缘|两手足同称谓、两个孩子、同名不同人；迁两次后 ID 不变，亲子无环、无自指，死亡冻结；活人最多一个经济户|
|婚史|候选缓议再见、成婚后迁户、丧偶再婚；同人记忆延续、旧配偶可查、当前婚姻至多一条；子女仍指实际父母|
|清算|父母同年死亡、负债高于私钱、奇数余款、有/无合格子女；同一亡者重复结算无变化，抵偿不超过私产，私债不转嫁未签约者；无继承人余额入实际所属户|
|家计|改户前后每户每项一致、死者不产出、照护少算一次；旧户仍欠债时不关闭，全零只关闭一次，无 NaN、负担重复或幽灵工人|
|事件|暂停不增年、不重复付钱；参与者去世或离户后既有承诺只执行或取消一次，照护和师承仍指原人；复工和 NPC 转业回放一致|
|历史和知识|同年异地 exposed/heard 分离；西汉配置不调用其他时代规则；普通人物页不显隐藏分数，终局才揭示应揭示的历史事实|
|确定性|相同种子、内容、配置和选择产生相同序列；四条黄金回放每一步比较；首次失配输出种子、年龄、命令、旧键、新键及字段路径|

当前未实现转换器，本轮没有迁移任何玩家数据。Stages 1–5 均待逐段批准。缺乏直接证据的史实、现代化婚姻假设、玩法调参和所有新出身均留在既有产品审查流程。
