# Phase 2B.3-B 提案 · 下次赶集，他还记得你

**待审设计。** 一名玩家能说出姓名、说清怎么认识的非亲属雇主，一次可以影响下次选择的交谈，足以验证这一片玩法。沿用每年两次行动及已有问工、赴约、回信流程。首版选一个地方、一类活、一名雇主；无合适关系的主角可以整年都没有这个入口。

## 一个可玩的例子

以下人名、对话、岗位及期限均是虚构样例。行商家的宁曾随家人运货，纪事里已有与布贩张平往来的记录。宁再次随同赶集，熟人当面引见张平。此时宁才知道其姓名与布匹生意。第一次问工，张平说“这趟布已经点完；下回带货单来，我看看你认不认得上面的字。”这次请求占一次行动；所得消息只揭示张平自己的要求。宁可以把另一次行动留给家里。后来习读经历满足条件，宁再见张平，他提起上次的货单，决定是否约谈。若只做过搬运，也可能约宁看货担；这两个机会对应不同任务与前置经历。

同是习读过的主角，只有实际发生过介绍或相识记录才认识张平。自耕或佃作出身也可以经运粮时结识他。若忙于照护、本人生病、无法抵达约定地点，展示可知的缺席缘由，并按已有规则中断或到期。欠债能解释为何家里急需劳力；单凭欠债不给雇主读心或否决的能力。搬离原户后保留相识往事，重新按地点与联系渠道判断能否再见。

## 小范围领域接口

| 建议操作 | 输入与结果 |
|---|---|
| 查询可联系雇主 | 输入当前人生与已发生的工作、习读或社会往来记录，输出玩家知道的姓名、介绍人、地点和可见要求。纯查询；未发生的介绍不生成 NPC 或抽样。 |
| 登记相识 | 在既有事件或行动提交成功时，按来源事件及雇主稳定键解析唯一 person ID，记录介绍人 ID、年份、地点及相识途径。以后从不同途径遇见同一雇主都指向这个 ID。 |
| 问工与赴约 | 复用 submitAnnual 的命令 ID 校验、预算、回执和邀约状态。目标是雇主本人；引路人另有字段。一次提交同时记录行动、可见结果及新的邀约。相同机会拒绝后保持原结果；有新的货批、约定时间或已展示的技能才开放新请求。 |
| 处理后续消息 | 年度结算后复核雇主、可达性与期限。到信免费；想亲自赴约再按已有规则消耗行动。面谈可结束于相识、明确的用工要求或一个有期限的回访机会。每个来源邀约至多产生一个后续机会。 |

身份整合是实施前的首要检查点。当前 register 可生成外部人物，却标记为 relative；旧投影也会检索非住户的 relative。建议在同一人物表中显式区分社会联系人，逐处检查校验、旧投影、亲属面板、婚议档案与继承遍历。以既有登记记录复用 ID，禁止按显示姓名去重。外部联系人不进入 residentOrder，不取得亲属关系、候选资格、户主权或分产份额。旧人生缺少联系记录时按空集合读；展示旧邀约仍解析其原始经手人，禁止改指新雇主。跳过主动行动时不提前占用人物编号或扰动年度随机序列。

记忆可以从双方真实发生的回执派生：人物 ID、机会 ID、年份、见面或拒绝、当时给出的可见理由、允许重问的条件。下次展示一句与事实对应的回顾。雇主可以拒绝曾见过的人；玩家可以放弃回访。关系持续到失联或死亡后仍可回顾，行动资格单独计算。玩家只能看见亲历或收到的消息；史料、隐藏关系评分及未知死因留在研究或调试层。

## 史料与取舍

- **原始记载。**《汉书》卷五十八《儿宽传》记千乘人儿宽贫困求学，曾赁作，锄作休息时读经。传主后来在武帝朝任职。这是一位有经学经历男子的回顾性传记，能支撑求学与受雇劳动并存；具体雇主、雇期、工价、引见程序及劳动地点在这段文字中均不明确。[原文](https://zh.wikisource.org/zh-hant/%E6%BC%A2%E6%9B%B8/%E5%8D%B7058)
- **学术解释。** Tsang Wing Ma讨论秦汉雇佣活动与人口流动，强调劳动力需求可能吸引劳动者移动。研究跨时期、地区及不同材料；不能据此给武帝朝某一县的自由编户设定统一工价、机会频率或流动自由度。[论文及英文摘要](https://www.basar.uni-freiburg.de/wp-content/uploads/2018/01/Tsang-Wing-Ma-Hired-Activities-and-Movement-of-Population-in-Qin-Han-Periods-2012.pdf)
- **设计假设。** 本片聚焦游戏既有自由编户成年角色。熟人引见、布匹货单及次年回访均属拟写。两次行动与十八岁开放是玩法尺度。史料不能支持的精确工资、农忙天数、性别禁令或出身专属职业，在获得同地域、身份、年代材料前不参数化。徭役、官府差遣和役属劳动另行研究。

## 工钱与工时的后续审查门槛

此片只记录关系、信息与邀约，问工、到信、面谈三者的账本变化均为零。后来若有实作，须先定义付款账户、劳动者、依法或依约收款账户、期间、报酬单位、履约与结算 ID。亲属引路或同住不构成付款授权。雇主没有可支出的真实余额时不能承诺一笔已担保的工资。实物与钱分别核算。

例：原应在自家田间劳动的三天若用于外户做工，年度产出须只计剩余可用劳动，雇主支付的报酬从其既有账户转入合法收款账户。三天是测试夹具。先决定家庭劳动如何按期分摊，避免在全年产出已结算后追记满额工资；可在约定后从下一未结算期间排期。照护、患病或雇主失约须明确已履约份额，按同一结算 ID 原子记账。账务及产出审查前保持访谈终点。

## 建议的本地验收

1. 用一对相同出身、不同实际经历的种子或固定夹具，显示只有认识引路人并到过相应地点的一方能接触张平；另验证不同出身可以经同一真实社会关系取得入口。
2. 同一雇主经两条渠道、跨年、读档后均为同一人；同名不同人不混淆。死亡、迁居、失联后仍能查看过去回执；支持旧邀约。检查亲属、候选、继承、人口及户账列表。
3. 拒绝留下具体理由。重放命令与对未变化机会的重复请求均不能刷新判定；有新条件时可获不同任务，仍允许被拒。复查打开、取消、免费来信及一约一次回访。
4. 本地浏览器复现“引见、被拒、获知要求、隔年再会”及“照护错过回访”两条路径；检查逐次反馈、双击、两次预算、期限和纪事中的人名。观察玩家是否能根据第一次消息改选第二次行动。
5. 对四个既有种子做浏览器回归，冻结的 1,000 个跳过行动人生逐个对照。按出身、居处、债务列出可达联系人、人年零机会、拒绝、信息、再遇、失约与使用次数。逐笔比对家庭账本、个人钱财与借贷；预算不产生报酬。
6. 原终局债务分歧继续作为独立经济调查。首版验收关注玩家是否记得一个人、为何能找他、上次交谈改变了什么；带薪劳动另行立项。
