# 03 — 连续人生模拟与长期因果（Simulation Engine）

## 1. 核心状态

`WorldState` = 年/月/地区经济与政治环境、历史事实；`PersonState` = 身体、年龄、技能、资源、家庭关系、所在地、职业、身份；`LifeMemory` = 人生事实、承诺、冲突、重大抉择与其因果来源；`StoryThreads` = 尚未解决的人生线索。

所有状态在本局浏览器内存中运行；不提供用户存档，但**局内必须持久**。

## 2. 家庭是模拟核心单位

- 出生生成：家庭身份、实际资源、父母职业、代际关系、兄弟姐妹、性别、地区、既有债务/资产。
- 现金流不是一个抽象的 wealth 点数：至少区分收入、基本支出、可支配资源、负债和少量耐久资产（田产/店铺/工具）；MVP 可做简化指数但保留扩展接口。
- 家庭成员有年龄、健康、生死、职业/官职（适用时）、目标与关系，死亡不得被后续事件引用为活人。婚姻需要保留两边家户、资产控制与姻亲关系，不以配偶单独一张卡代替。
- 婚配、分家、继承、赡养、移居与入仕可改变家庭成员及资源网络。
- 世代累计：玩家自己的子女可以成长，亦可影响晚年、但 MVP 不允许转生接管子女作为多代存档。

## 3. 角色与性别

- 生理/身体健康风险与社会性别身份规则分离建模，避免仅用一个 `gender` 控制所有事件。
- 不同历史时期的婚姻、财产、教育、官职、迁居可能受身份与性别共同制约，保留**例外机制**和史料来源。
- 女性角色同样有复杂发展路线，例如持家、劳动、商贸参与、教育、宗教/文化活动、政治影响（具体依法制与时代实现）；不应该把所有事件压缩为嫁人或入宫。
- 不应强制每个角色都会婚配、生育或遭遇同样的身体事件。

## 4. 年度/季节更新顺序

1. 推进世界时钟、应用史实节点及持续性冲击。
2. 更新区域产出、物价、交通、安全、人口迁移与疾病暴露。
3. 更新家庭经济、NPC 行为与社会关系。
4. 结算年龄、健康、教育/技能积累、职业、育儿、债务。
5. 处理待执行的延迟后果、故事线索和事件资格。
6. 根据条件与权重抽取生活事件、关键抉择；必要时暂停。
7. 执行决策，登记事件、关系变化、因果引用与角色可得情报。
8. 生成**角色视角**年谱；可选快进下一段无重大转折时光。

需要一个任务/事件调度队列，支持“23 岁结亲，31 岁因婚姻资源获得经营机会”和“15 岁迁徙，40 岁因旧地关系受益/受累”。

## 5. 长期因果系统（最核心）

每个关键选择记录：

```ts
interface DecisionRecord {
  id: string;
  year: number;
  age: number;
  decisionId: string;
  optionId: string;
  immediateEffects: EffectRecord[];
  persistentFlags: string[];
  scheduledConsequences: ScheduledConsequence[];
  changedRelationships: RelationshipDelta[];
  causalLinks: string[];
}
```

一条结果可以有**多个原因**，不能把所有事件写成“一旦选 A，25 年后必定 B”。

示例：15 岁离乡学艺

- 即时：家庭积蓄减少、离开故乡、认识师傅。
- 18 岁：若学艺持续，技能上升；也可能因病、战乱或经济压力中断。
- 25 岁：有资格参加新的职业机会事件池；旧乡关系下降。
- 40 岁：有机会经营作坊、扶持子女学艺、或因长期离乡与母亲疏远。
- 生平回顾：显示「40 岁作坊开张」与「15 岁离乡」之间的可解释因果，**并非必然成功**。

## 6. 长期状态：比数值条重要

`occupation`, `placeHistory`, `kinship`, `skills`, `property`, `debts`, `reputationByGroup`, `chronicConditions`, `educationAccess`, `politicalExposure`, `unresolvedThreads`。

**防遗忘**：对于每个被选中的重要事件，必须记录永久或有期限的事实。事件选取需要同时查看长期事实与现实世界条件。

## 7. 区域疾病机制

流程：`regional hazard` → `household contact/exposure` → `infection likelihood` → `outcome conditional on age, baseline health, resources`。

- 疫病史料常存在地点记载密度、病名和传播机制不确定性，**不得用已知的现代确诊病名填补所有古代疫病**。
- 气候、战争、逃难、住房拥挤、食物条件可以是风险因子，但应谨慎估计/校准；不要把某地区永久标记为“必然得某种病”。
- 玩家可能完全不受同一个地区疫病影响，也可能因家人患病改变经济和人生路线。
- 年龄/健康风险需要合理，不可简单每年独立掷相同死亡率；死亡是终局状态并阻断后续人生事件。

## 8. Living NPC / 家庭网络（详细规范见 09）

核心原则：**重要 NPC 不以玩家为中心存在**。MVP 维持约 3–8 名 Tier 1 核心 NPC 和 5–12 名 Tier 2 重要社会人物（实际数随人生与性能调整）；背景人物只有必要时实例化。年岁推进时他们会自主学习、谋生、考试、求职、改换行业、经营资产、婚育、患病、迁移或死亡；每一步须符合时代、性别、身份和年龄规则。

- NPC 有稳定身份（id、家户、亲属、年龄、职位/官职、所在地）与稳定但非绝对固定的性格维度、目标、利益约束；有可变的健康、资源、经历、关系与主观知识。
- “父母同意/反对、配偶是否愿意合作”属于 **NPC 决策**：考虑性格、欲望、家庭经济、制度、当前风险、彼此关系、已知信息，然后按合理权重裁决。**不能只做 `trust >= 60` 的阈值开关**，也不能仅因好感度高就顺从玩家。
- 婚姻创建或修改夫家/妻家等姻亲网络，并引入家产控制权、居住归属、继承/嫁妆和责任义务；这些规则按时代及具体情况配置，**并非每局都有完整的公婆、长兄、长嫂**。
- `RelationshipState` 至少区分亲近、信任、利益、权力/依赖，不使用一个“好感度”解释一切；重要互动写入 NPC 专属记忆与 `CausalLedger`。
- 玩家可见的是可观察事实、转述、对人的印象和不确定性；**不暴露隐藏性格、真实意图和固定数值**。
- 不使用 LLM 驱动日常 NPC；规则引擎 + 有限状态/目标选择即可。详细数据契约与三层 NPC 模拟频率见 `09_LIVING_NPC_AND_HOUSEHOLDS.md`。


## 9. 随机性原则

- 使用 seedable RNG，按世界/家庭/人物/事件分子流，减少内容调整引起的随机序列级联偏移。
- 条件采样优先：先选时代与地区，再选身份、家庭，再按家庭约束选资源与教育机会。
- 有 `no-event`、失败、普通结果，不要只堆极端事件。
- 引入事件冷却、重复限制和情绪节奏，不允许同一人物三年内连续出现五个同类离奇事件。
- 避免历史之外的硬保底传奇成功；少数奇遇可存在，但不得常态化。

## 10. 不变量

- 死者不会行动；未出生者不会成婚；角色不能在未迁移的同一年同时身处两个地区。
- 一件重要财产不在多个家庭无限重复转移；收入支出避免负数无界。
- 身份变化有合法路径、时间和地域约束；无资格不能直接触发对应事件。
- 任何触发的故事都应能解释是哪些当前条件和旧选择使它出现。

## v1.3 年度主动行动、隐藏禀赋与状态分离

- 增设年度主动行动额度（成年默认 2 次/年）；一次主动行为与年度自动结算（谋生、家庭生产、健康、NPC 自主生活）是不同概念，**不因玩家没点“工作”就令角色没有全年生计**。重大被动事件的回应通常不耗额度。行动按年龄、身份、健康、家长约束和历史资格过滤。
- 主角及 Tier 1 NPC 可拥有隐藏的相对稳定**悟性、专长禀赋**，以及相对可塑的**通情、勤勉、韧性**；已有 `talent`、`skill`、`practice` 与 NPC 个性须先做读取/写入审计再重构，避免平行重复字段。专长可能为零或不突出；从未得到学习机会者可能终身不知自己擅长什么。
- 明确区分：先天倾向、可塑天性、通过实践习得的技能、已获得知识、身体健康、角色社会身份。不得从“悟性高”直接推出必然学有所成；不能无限重复行动刷先天属性。
- 家户按照同住成员、可用劳动能力与共同资源结算，玩家个人荷包独立；分家后原家户债务不自动转移；父母死亡必须先处理实际遗产与有效债务义务及留居成员，才能关闭无关家户。
- 经济、婚姻、死亡、教育的校准必须用固定种子、多个行动策略、分出身/性别/年龄分层比较，**不可通过强制成功率使人生趋同**。

## P0 · 从家庭事实生成机会

出生时记录时期、地区、亲缘和初始家户；逐年从当前同住者、资产、可支配资金、亲友和照护责任判断机会。家庭有货担，可能让孩子接触计量；还须有愿教的同行、合适的时机和实际练习，才可能形成习得技能。若同行离开，后续学习须另找途径，已经学会的本领保留。隐藏禀赋按人物独立取样，出身影响能否接触、练习和得到反馈。事件与年谱保留同一参与者和前因，职业、健康、婚居或家计变化后重新计算资格。成年每年两次主动行动、响应事件和 NPC 自主行动分别结算。
