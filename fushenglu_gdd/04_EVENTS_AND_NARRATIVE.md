# 04 — 事件、角色认知与叙事（Event & Choice / Narrative Engine）

## 1. 事件分类

- **环境变化**：区域战乱、粮价、农作收成、疫病、迁移；可不形成玩家可见剧情。
- **日常纪事**：亲属来往、劳作、学习、交易、身体变化；短文本，可自动结算。
- **重大人生事件**：疾病、议亲与婚姻、职业变化、家业衰落、迁徙、亲人去世；记录因果与回忆。
- **关键选择**：选择是否读书、卖田、迁居、参军、接受婚事等；受角色的实际行动空间约束。
- **历史交汇**：玩家处于真实历史事件的影响网络中，但**并非所有人都看见史实的全貌**。

## 2. 事件结构

```ts
interface LifeEventTemplate {
  id: string;
  category: 'mundane'|'milestone'|'choice'|'historical-contact';
  when: { minAge?: number; maxAge?: number; years?: number[] };
  eligibility: Condition[];        // 包括时期、地区、身份和 life facts
  weight: number;                 // 游戏抽样权重，不自动等同历史频率
  cooldownYears?: number;
  maxPerLife?: number;
  storyThread?: { creates?: string[]; advances?: string[]; closes?: string[] };
  narrative: NarrativeVariant[];  // 文案按角色视角/地域/阶层/NPC性格和已知事实取不同版本
  choices?: ChoiceOption[];
  defaultEffects?: Effect[];
  evidenceLevel: 'documented'|'inferred'|'gameplay';
}
```

`ChoiceOption` 应有显示文案、已知风险、约束条件、即时效果、延迟效果、可追溯的 `causes`，且可以产生失败或模糊结果。玩家看不到内部数值阈值。

## 3. 事件选择算法

1. 筛除时代/地理/年龄/身份/生死/家庭/历史事实不匹配的模板；需要特定人物在场的事件还须核对 NPC 存活、地点、关系、角色知识和可用资源。
2. 检查 `StoryThreads` 是否需要优先推进；防止长期伏笔永远没有下文。
3. 使用权重（基础 × 地区冲击 × 家庭/关系 × 过去经历 × 节奏控制）抽取。
4. 生成角色视角文本（直接目睹、传闻、局部经济影响）；**不可把系统内部历史名称直接泄漏到角色界面**。
5. 玩家选择先提交 **行动意图**，涉及他人的请求由 NPC Decision Resolver 裁决；再原子性地写入世界状态、人物状态、NPC 记忆、家庭网络和因果日志。
6. 校验不变量，再继续推进。

## 4. 典型视角切换：755 年安史之乱（将来唐朝内容）

以下全部为**原创游戏文案示例，不是具体史料或真实人物经历**。

### 近战区农户

「村口又有兵马经过。阿父藏起仅剩的粮袋，说若再征一次，今年恐怕难熬。」

- 主角可推断：征发增加、村落不安全。
- 主角不一定知道：战争名称、后续皇帝命运。
- 选择：躲避征发 / 迁往亲族所在地区 / 留守田地。
- 后果：资产、健康、亲属分离、未来地区与职业机会。

### 交通枢纽商户

「昨日说好的丝绸今日仍未运到，城里米价忽然不稳。商队的人只说北路不太平。」

- 认知：运输与交易风险；关于军事的传闻。
- 选择：囤货 / 改道 / 关门保本。
- 后果：亏损或盈利、声誉、供应链关系变化。

### 朝廷官员家属

「父亲整夜没有卸下官服，连平日的客人也闭门不见。府中仆役悄悄在整理行囊。」

- 认知：可能提前得到消息，但不是全知。
- 后果：政治风险、迁徙、家族信任与前途。

### 偏远地区人物

可能**当年完全没有弹窗**。数年后若有流民迁入、赋役变化或商路改道，才用当地生活事件体现。不要给该人物无缘无故弹出「安史之乱爆发」提示。

## 5. 三层叙事信息

| 层级 | 何时可见 | 示例 |
| --- | --- | --- |
| `observation` 观察 | 当下 | 「盐价上涨」「父亲接到一封信」 |
| `interpretation` 认知 | 依据人物渠道 | 「有人说边镇有变」 |
| `historical_truth` 史实 | 默认终局揭示 | 「这些变化与某次战乱、政策调整有关」 |

同一事件可能产生多个观察结果；认知可能错误。玩家界面可以呈现不确定性，但系统内部必须知道哪条是史实、哪条只是传闻。

## 6. 终局：历史揭示是产品招牌

按三个并列视角展示：

1. **这一生**：人生主要年份/人物、选择与直接后果。
2. **彼时天下**：这一生跨越了哪些确定的历史节点，哪些是主角可能不知道的。
3. **命运回声**：例如「15 岁选择离乡」如何改变「40 岁谋生与亲属关系」；用 `causalLinks` 追溯，禁止 AI 或文案凭空虚构原因。

历史揭示按：事实 → 地区影响 → 家庭结果 → 主角实际获知程度。支持展开简短来源链接与史料可信度。

### 示范

> 你于某年离开故乡，此后辗转营生。那一年，你只知道商路渐断。多年后史书将这一连串动乱称为安史之乱。它并未直接毁掉你的家，却改写了你谋生的道路。

示范不保证每个角色都被同一史实影响。

## 7. 历史人物类比

结局后匹配真实人物的**时代/身份背景、职业轨迹、家族经历、关键转折、生活主题**；先做分类检索，再做有解释的相似度排序。不得把缺乏资料的普通人硬凑成帝王将相；可以显示「更像某类历史生活轨迹，暂无可考的具体人物」。所有人物条目有可信来源，不将文学作品改编当作史实。

## 8. 文案质量守则

- 忌现代全知口吻、现代省市名称、跨朝代术语混用、强行爽文、所有人物一律使用现代价值判断。
- 短事件控制信息密度；重大节点可以更有文学性，但不要每年长段文字。
- 某些人生平淡仍应该有可读的生活细节与情感递进。
- 可以展示未知/传闻；不能让叙述者在无提示情况下把流言当真相。
- 事件必须可进行数值/规则验证和史料审校，内容与逻辑数据分离便于本地化。

## 9. 人物活人感的文游叙事规范（v1.1）

- 同一个选项面对不同 NPC，不可仅换人名：反馈必须因人格特质、关系、当下目标、家族利益、既往记忆而改变。
- **展示行为，不揭露标签**：写“婆母将钥匙收进袖中，仍未提起让你管账”，不写“婆母控制欲 78，嫉妒 +5”。重要角色的职业、已知官职、年龄与家族位置可以在「人物志」查阅；隐藏动机与心理评分不可见。
- **媒人/家人的转述不是系统真相**。资料卡需区分“亲眼所见 / 传闻 / 尚不清楚”，关系亲近也不意味着知道对方心里所有事。
- 事件中人物说“不”应有**可解释的多因决策**：同意与否还可能受到第三人的施压、资产现状和社会风险影响。
- 日常 NPC 变化可以很短：“陆怀瑾又一次落第；这次，他没有将信拿给你看。”无需每次扩写成长篇对话。
- 重要 NPC 不能在多个年份重复同一段未经解释的初次见面/职业状态；每条重大人物线至少支持一个后续回响和一次合理收束。
- 在婚嫁事件中，婚配是**家户网络转换**，而非“婚姻=true”：关键姻亲人物应随身份结构出现，且不必人人好相处。见 `09_LIVING_NPC_AND_HOUSEHOLDS.md`。

## 10. v1.2 消息流、分层文本与实施减法

- 世界行情、天气、道路、时局传闻以独立短消息进入「见闻流」，不可为了交代历史背景而要求父母/配偶长篇复述天下局势。
- 日常纪事用短事件，重大决策采用精修的可分段文本。事件可组合，但严禁为追求变体数量把大量碎片自由拼接导致人物/年代不一致。
- 基础模式不使用实时 AI：预制事件模板 + 条件变体 + NPC 决策规则 + 因果记录。开发阶段用 AI 辅助写作可以，但玩家端不触发 API。
- 知情程度影响可选行动的机制仅作**可选的稀疏布尔标记**；MVP 不实现完整知识图谱、推理链和谣言传播。详见 `11_REGIONAL_THEMES_AND_NO_AI_NARRATIVE.md`。
