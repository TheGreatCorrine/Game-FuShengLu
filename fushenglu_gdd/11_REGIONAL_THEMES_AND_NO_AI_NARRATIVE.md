# 11 — 地域主题与零 AI 叙事实施规范（v1.2）

> 状态：已确定的 UI/成本边界 + 渐进实现方案。本文件规范视觉主题和叙事系统的**实现范围**，不得把可选机制误认为 MVP 必须完成。

## 1. 统一 UI，地区只改变表现层

**MUST**：所有地域主题共用同一信息架构、组件结构、交互操作、导航顺序、文字字号体系与可访问性规则。主题不改变剧情事件、属性数值、选项概率、文本可见权限。不能按地域分别造页面。

全局维持「现代极简水墨」：瓷白、墨黑、青绿、少量朱砂。**不使用重度黄褐旧纸色、密集边框、翻书动画或大面积角色立绘**。主题差异仅限 CSS tokens、极淡局部背景水墨纹样、有限的地域装饰元素；所有文本须保持清晰对比度。绝大部分页面保持浅色和留白。

## 2. 主界面三种文字信息，不是「翻书」

1. **世界消息 / 见闻**：一条一条出现；当地粮价、布价、道路、天气、传闻等，附来源或确定性暗示。可回看，未闻之事不得显示；不强迫每条都出现弹窗。
2. **人生纪事**：短片段表现家庭、职业、关系和个人变化。可按年份或阶段滚动推进。
3. **重大事件 / 关键抉择**：必要时展开较完整的文本，包括铺垫、角色反应和选择，不能只有两行提要，也不能把所有事件铺成超长书页。

同一事件可产生世界状态变化、若干条见闻和一个人生事件，但必须用去重键防止相同消息反复推送。**历史重大事件不会自动变成全知公告**；终局解锁历史真相。

## 3. 姓名与收集

- 出生时先随机确定家族姓氏，玩家可输入或随机生成「名」；最终确认后 **姓与名都锁定，整局不可更改**。称谓、封号、官职可变，但不能覆盖原始姓名。
- 不做完整局的云存档或账号。MVP 的收藏图鉴可以**不持久化**；未来如果需要跨局收集，可选少量 `localStorage` 收藏 ID，不含人生进程或 NPC 资料，须明确告知用户浏览器清除数据会丢失，也无法跨设备同步。
- CG 属后期扩展：结局/历史人物/成语图鉴可配少量插画；MVP 纯文字与图标即可完成核心体验。

## 4. 零在线 AI 的叙事方案

正式基础模式 **MUST** 使用人工审阅的预设素材，不在玩家游玩期间调用模型 API：
- 世界消息：短模板 + 历史状态/地点/玩家认知条件；
- 人生纪事：事件骨架 + 少量条件段落；
- 重大事件：少数经过精修的分支文本 + NPC 反馈；
- 结局：人生因果记录归纳 + 历史事实解密 + 有依据的历史人物类比。

开发阶段可以使用 AI 辅助起草、整理与审核**离线内容**，必须人工与规则校验后静态打包。文字深度由**精选完整模板**承担，不依赖把 20 个碎片随机拼在一起。采用少数互斥变体避免语法、称谓、时间与人物逻辑矛盾。

## 5. 「知道更多解锁选项」：简化，不做推理系统

此机制 **MAY**，不是 MVP 关键依赖。首发最多 2–3 个**明确的布尔知识标记**，仅作用于极少数特别事件：
- `knows_trade_route_risk`：曾从商队获得可信消息；
- `knows_household_debt`：实际接触过账本；
- `knows_suitor_background`：通过媒人/亲友得知议亲对象部分情况。

处理规则：选项先按年龄、法律/社会身份、资源、人物关系判断是否可行；仅个别选项附加 `requiredKnowledgeFlag`。**未得到知识不等于必定失败**，它只可能影响选项是否出现、提示精度或结果权重。玩家永远可使用基础可行选项。不要引入知识点图谱、谣言传播智能体、多层情报推理及动态 NPC 对话来支撑这个功能。

## 6. 工程边界与验收

- 同一个布局组件在不同地区仅由 `themeId` 选择 CSS tokens 与装饰背景；切主题后所有按钮功能/数据相同。
- 离线运行（首次加载静态资源后无模型请求），无云存档、无账号、无按回合付费调用。
- 见闻列表的「消息产生」「角色是否有渠道知道」「显示时机」可分别测试；不把事件真相直接灌入 NPC 台词。
- 使用同一种子时主题颜色切换不得改变剧情结果；人物姓名确认后所有 UI 都只读。
- 初期不要求知识标记驱动复杂分支，先验证历史区域差异与长期因果这两项核心指标。
