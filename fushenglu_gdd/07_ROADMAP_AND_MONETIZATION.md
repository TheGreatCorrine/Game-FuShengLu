# 07 — 迭代路线、范围与商业化

## 1. 研发顺序（按风险验证，而非按页面）

### M0 — 数据与规则骨架

- 建立统一年份编码、历史规则 schema、地区模型、可复现 PRNG、游戏状态不变量。
- 选定西汉一个具体历史窗口、3 个地区与 4 类家庭作为示范。
- 写 1 个真实历史主轴事件及地区扩散机制，证实可以有直接/间接/无明显影响三种结果。

### M1 — 纵向可玩切片

- 出生 → 成长 → 15 岁关键选择 → 长期状态 → 40 岁结果 → 终局揭示。
- 至少 2 条完整因果线和数个随机 NPC，验证未来事件能读取过去选择；另外验证两位不同性格的父母在相同请求下可能作出不同决定。
- 人生回顾能明确标出来源于真实历史的变化与个人选择。

### M2 — 西汉最小完整游戏

- 可走完从出生到死亡的一生；婚配/家庭/职业/疾病/生计基础系统。**婚配必须产生关键姻亲及家户变化**；核心 NPC 按年自主成长。
- 约 80–150 个高质量且可组合的事件模板是**内容计划范围**，不是必须先写完的研发门槛。
- 明确性别×身份规则、地区差异、历史节点、内容史料标注与终局历史人物类比。
- 可在手机浏览器运行。静态托管，无账号、无保存。

### M3 — 真实历史多时期

- 先扩展西汉内部时段与东汉，再添加新的历史阶段；每次添加新时期必须提供独有制度/社会/历史冲击，而非换皮。
- 加入迁徙图、交通与贸易连接、更多具有可追踪长期影响的地区事件。

### M4 — 付费扩展（不是首发依赖）

- 历史名人亲属/熟人开局：绑定经过审校的真实人物履历与交汇资格，不允许虚构内容冒充史实。
- 架空史线 AI 模式：变动有边界、收费与额度控制、后端校验所有提案。
- 可按玩家反馈决定是否做；不应让基础游戏缺功能以强迫付费。

## 2. 优先级

| 优先级 | 做什么 | 为什么 |
| --- | --- | --- |
| P0 | 年代/地区/身份约束，历史主轴 | 防止伪历史与同质化 |
| P0 | 连续状态、NPC 生死、因果记录、关键 NPC 自主行为与关系记忆 | 让玩家 15 岁决定影响 40 岁，人物不是工具人 |
| P0 | 有限视角与终局历史揭示 | 最具辨识度的体验 |
| P1 | 更多生活事件、夫家/姻亲网络、家庭经济/关系、结局匹配 | 提升复玩性 |
| P1 | 强化地区病疫与经济模型 | 提高模拟真实性 |
| P2 | 更华丽的视觉、更多时代、多种模式 | 在可玩性验证后扩充 |
| P3 | AI 改史、历史名人亲属付费开局 | 非核心、成本更高 |

## 3. 费用与运营

- 免费单机游戏：大部分计算发生在玩家浏览器；内容编译为静态资源。运营费用主要来自静态托管域名、资源分发和可选分析；不需要为每一次选择调用 API。
- 不需要向服务器上传游戏进度；结果可在玩家端渲染。
- 若做每日统计或排行榜，则另外评估服务器和隐私，不是当前设计的一部分。
- AI 分支成本与 token 使用量、模型、生成内容长度和调用次数有关；定价前必须基于实测成本与使用率建模。
- 建议「有限次改史包」而不是无限生成订阅，拥有后台成本上限、异常告警与功能降级。

## 4. 不变的付费设计边界

- 付费不能成为理解历史、完成一段基础人生或查看终局揭示的前提。
- 生成式 AI 只用于**显式可选**的架空路线，不用于强制解锁的正常历史叙事。
- 真实历史人物亲属开局属于可选的情景设定，并应明确标注架空之处。
- 不向未成年人暗示赌博式充值；不使用随机付费抽卡来购买“更好的人生”。

## 5. 开发前的三个决策门

1. 西汉第一个出生时间段定为哪几年？需考虑年龄覆盖、历史节点和资料可获得性。
2. 地理颗粒度：先按 3–5 个历史区域，未来精确至郡县；不因过早追求地图细节延迟玩法验证。
3. 首版健康/经济如何做最小可信模型？宁可诚实用模拟指数，也不把缺乏证据的精确值当史实。

## 6. 发布门槛

至少通过两个北极星用例和新增的 NPC 自主连续性用例、无明显时代/身份逻辑错误、无 NPC 死亡复活、角色不能提前得知史事、多个基础出身的平凡人生都能完成、无账号无存档、离线逻辑不调用 AI。

## 7. v1.1 范围与性能门槛

- **纵向切片**：先做父母/手足等少数 NPC 的真实自主状态变化、一次父母请求协商，以及条件性的婚配后家庭网络；证明引擎能力，不要求立刻制作所有姻亲剧本。
- **首版完整西汉人生**：核心 NPC 目标 3–8 人，重要 NPC 5–12 人；超过该数量时按远近关系降采样或转成简化更新。数量为工程预算，不是每局必须生成的名单。
- 每条重要人物关系至少要有初识/转变/回响或收束之一，避免凭空消失；长年未见可以通过合理失联而非无视状态来解释。
- 纯文字主屏 + 人物志 + 荷包 + 年谱是 P0；大图、立绘、即时自由对话均非首版依赖。

## 8. v1.2 范围控制补充

- UI：**先一个通用布局 + 3 套地域颜色/极淡背景**，之后拓展至 3–10 套。迁居时可以换 themeId，但不得让主题工程阻碍模拟原型。
- 文案：先实现三层信息流（见闻/纪事/重大事件），使用离线模板，不按玩家生成收费文本。
- 知识解锁专属选项是 P2 可选功能；MVP 最多只示范 1–2 个明确的已知条件，不开发推理系统。
- 姓名只在出生时确认一次；结局 CG/图鉴持久化不是 MVP 阻塞项。

## v1.3 阶段安排（优先于堆新内容）

1. **Phase 2A.1 Stage A：设计审核**——基于真实源码跑基线；形成经济、人生/婚姻、健康能力、社会身份四张设计表，再补年度行动/市集、隐藏天资设计表，记录历史证据与需要设计者批准的假设。**未经确认不要大量改平衡参数**。
2. **Phase 2A.1 Stage B：校准与纠错**——设计确认后修经济赤字偏向、婚龄与婚配推进、资格 Bug、重复选择和主屏财务信息；比较多策略模拟结果。
3. **Phase 2B：人物人生弧线**——NPC 长期目标、家人间关系、自主互动、伴侣/父母对婚事和解除婚姻的回应；一条人物线应有开端、变化、回响/收束。
4. **Phase 2C：社会身份差异**——依西汉研究补充性别×出身×地域×法律资格的人生路径，避免二分法和全时代通用规则。
5. **后续**——逐步实现市集、更多历史生活内容及《当朝律令》可查阅功能；严重债役/人口典卖须先研究合法性与社会实践，不得抢先造剧情。
