# 09 — Living NPC 与家庭网络系统（v1.1）

> 目标：**NPC 是与主角同处一个历史世界、拥有自身生活的人**；不依赖每回合 AI，也不让玩家以“选择”直接控制其意志。本文是 `03/04/05` 的人物模拟详细规范。

## 1. 设计原则

1. **独立人生**：父母、手足、配偶、子女、师友与关键姻亲随时钟自主变化；不出场 ≠ 停止生活。
2. **局内连续**：每个人稳定 `personId`，姓名、出生、亲属关系、重大经历可追溯；迁居、婚配或改职业不生成新人覆盖旧人。
3. **人格影响行动，不决定一切**：性格是倾向，不是固定对白表；制度、现实利益、关系、压力与知识可压倒人格倾向。
4. **玩家的认知有限**：人物志仅显示确知事实、观察印象、传闻及未知；NPC 心理/决策权重隐藏。
5. **婚姻是家户联结**：关联两边亲族、住所、权力、资产和照料责任，而不是修改 `married=true`。
6. **时代优先**：可婚配年龄、法律身份、科举/察举/任官、财产权、户籍、亲属称谓由对应朝代 ruleset 和证据约束。

## 2. 人物层级与计算预算

| 层级 | 例子 | 必要模拟 | 建议预算 |
|---|---|---|---|
| Tier 1 核心 | 父母、配偶、子女、最重要手足 | 独立目标、职业、状态、双向关系、关键记忆、年度行动 | 每局约 3–8 人 |
| Tier 2 重要 | 公婆/岳父母、主要兄嫂、师傅、朋友、上司 | 基础目标/性格、定期状态更新、关系与重要事件 | 每局约 5–12 人 |
| Tier 3 背景 | 媒人、陌生商旅、邻居 | 轻量身份；出现重要关系才提升层级 | 按需生成 |

层级按与玩家现实联系动态调整；离世人物保留历史和关系数据但不参与行动。规模是设计预算而非必须出现的人物数。无必要不模拟整座城市。

## 3. 身份、人格、状态与知识分离

- **身份事实**：`personId`, `birthYear`, `sex/socialStatus`, `residence`, `householdId`, `kinLinks`, `occupation`, `officeHistory`, `maritalStatus`, `alive`。
- **稳定人格（隐藏）**：责任心、野心、独立性、风险偏好、控制倾向、共情能力、勤勉；数值仅是模型内部参数，随年龄/重大经历可有限调整。
- **当前状态（变化）**：健康、疲劳/压力、资源支配、收入、职业进展、现实压力、目标/计划、权力依赖。
- **关系状态（双向且不对称）**：亲近、信任、利益一致、义务、冲突、影响力/依赖；A 对 B 的信任可与 B 对 A 不同。
- **记忆与知识**：亲历、听闻、承诺、恩惠、债务、失信、丧亲、落第、迁徙；存时间和 provenance。记忆可以淡化，重大事实不可无故消失。

建议数据形状（**伪 TypeScript，字段可进一步拆分**）：

```ts
interface LivingPerson {
  id: string;
  birthYear: number;
  householdId: string;
  residenceRegionId: string;
  occupationId?: string;
  offices: { officeId: string; startYear: number; endYear?: number }[];
  traits: Record<string, number>;             // INTERNAL ONLY
  goals: { id: string; priority: number; status: 'active'|'done'|'abandoned' }[];
  pressures: string[];
  relationships: Record<string, RelationshipState>;
  memories: MemoryRecord[];
  knowledge: KnowledgeEntry[];
  alive: boolean;
}
interface RelationshipState {
  closeness: number; trust: number; interestAlignment: number;
  obligations: string[]; conflicts: string[]; authority?: string;
}
```

## 4. NPC 自主行动流程

每月/季节/年度（取决于事件精度）：

1. 应用已发生的世界冲击与家庭资源变化。
2. 若 NPC 仍存活且可行动，根据年龄、工作/职位、角色目标及当前压力生成 `CandidateActions`。
3. 根据时代资格与现实条件删除不可能行动，按目标与人格计算效用/权重，加入有限随机性。
4. 结算成本、风险、失败与后果：例，备考可以落第或中选、经营可以亏损、求医可能无效。
5. 更新家庭财务、人物状态、关系、职业/官职历史与记忆，登记到因果账簿。
6. **仅当玩家有途径得知时**，把变化写进人物志或当年纪事。否则保留为未知事实。

不强制每年重大变化；普通日常也可提升技能、积累疲劳或保持状态。

## 5. NPC 对玩家请求的裁决

玩家点击的是“提出请求 / 表达立场 / 付出行动”，不是“强制使父亲同意”。示例：请父亲允许延迟议亲。

- 先做**硬约束**检查：人物是否存活、在场/可通信、本人是否有权决定、时代是否合法、是否具备可行资源。
- 再聚合**软因素**：家长门第观念、务实程度、债务压力、子女既往贡献、其他家人的支持、婚约既有承诺、政治与社会风险。
- 计算可接受范围与权重，使用局内确定性随机流决出：`agree | negotiate | refuse | postpone`。
- 返回 `reasonCodes`（如 `family_debt`, `trust_earned`, `status_pressure`, `mother_intervened`）给叙事引擎；不能原样泄露隐藏属性。
- **拒绝不等于游戏结束**：后续可以妥协、另谋路径、请求其他家人的支持，或者承担拒绝造成的后果。

> 禁止 `father.trust >= 60` 直接决定全部结果。相同请求、不同人产生不同决定是设计目标，但不是要求不同人永远走不同分支。

## 6. 夫家/姻亲 Household Graph

关系应建成图，而不是一次性生成“婆婆、丈夫、长嫂”固定套餐。

- **人**：`Person` 唯一 ID、出生/死亡、状态。
- **家户**：`Household` 成员、共居、资产、债务、收入与财务权限。
- **亲属/姻亲边**：血缘、婚姻、收养/过继、继亲、妯娌或其他可由关系计算的称谓；每条有起止时间与效力。
- **婚事**：通过议亲/家庭协商/礼法合规判断，变更居所与家户成员资格，登记陪嫁/嫁妆或相关财物控制权（依时期而异），维护娘家与姻亲关系。
- **婚后**：配偶仍有工作与目标，公婆/岳父母等人物有自己的喜恶和资源。财务决策需考虑“谁拥有、谁保管、谁有权支配”，不可自动把夫家家产算成玩家荷包。
- **死亡与再婚**：同步更新配偶关系、家庭结构、继承/监护/赡养责任。是否能再婚以及实际限制由时代制度、社会惯例与具体身份判断。

例：玩家嫁入士人家庭。丈夫可能落第、改业、出仕或病故；婆母可能掌账、让权或离世；长嫂可能与玩家合作或竞争。**这些事件都必须以存在的 NPC 和真实家户资源为前提**。

## 7. 玩家能够看到多少？

| 人物字段 | 界面 | 备注 |
|---|---|---|
| 姓名、已知年龄、关系 | 通常可见 | 年龄也可能仅估计 |
| 职业/官职及履历 | 已知时可见 | 不认识时显示“听闻在县署任职”等 |
| 家庭、居所、表面家境 | 视交往可见 | 可与实际财务不同 |
| 外在性情 | 逐渐形成的文字印象 | 如“寡言、守礼”，不是人格评分 |
| 真实目标、控制欲、信任数值 | **不可见** | 通过言行渐渐推断 |
| 媒人口述、道听途说 | 可以显示为**传闻** | 可能不准确 |
| 两人过去共同经历 | 从人生年谱可查看 | 但不能查看其未公开私密记忆 |

人物志使用 `ObservedPersonProfile` 计算呈现，不读取底层内部数值生成 UI 提示。

## 8. 文游片段：同一选择，不同的人

**宋朝示例，仅为虚构情节；历史制度资格另查。**

> 丈夫落第后独坐书房，桌上摆着父亲寄来的书信。你打算拿出嫁妆的一部分资助他继续读书。

- 丈夫甲：重情义、对家计谨慎 → 感激，但请求先减少其他开销。
- 丈夫乙：自尊强、急于证明自己 → 误以为被轻视，拒绝资助。
- 丈夫丙：仕途心切、缺乏节制 → 接受资助，却可能日后反复索取。

以上是**条件化结果示例**，不是人格标签到单一固定反馈的死映射。共同生活的财务、过往互动和家族干预可以改变结果。

## 9. 故障与反模式

- 禁止“所有丈夫都只有读书/升官/病死三个剧情”或按 NPC 名字写死剧情。
- 禁止 NPC 在不见玩家期间年龄停滞、职位永远不变、伤病无后果。
- 禁止死者出场行动、同一人被多家户复制成多个活人、凭空创造官职或财产。
- 禁止好感度高就无条件顺从，或自动将婚姻算作玩家获得夫家所有资产。
- 禁止 NPC 拥有超出自己渠道的历史真相；被骗/误解/失联要能成立。
- 不模拟每个背景人物的完整人生，避免性能和内容工作量爆炸。

## 10. 验收标准

1. 相同请求在不同人格和经济压力下可得到不同合理响应，且 `reasonCodes` 可追踪。
2. 玩家五年不主动联系某核心 NPC，五年后人物年龄、健康/职业/目标与家庭经历合理推进。
3. 婚姻创建/变更亲属、家户、居住和资源支配关系；娘家不会被覆盖消失。
4. 媒人的赞誉是传闻而非系统真相，人物志能够在接触后修正印象。
5. 随机种子固定时 NPC 事件可重演，无死者行动或时代非法任官。
6. 重要 NPC 的某个旧决定会影响未来至少一次事件权重、资格或关系，而非永远只修改临时心情。
